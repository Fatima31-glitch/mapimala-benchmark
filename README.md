# MAPIMALA — a reproducible low-compute benchmark for medicinal-plant identification (DIMPSAR, 40 species)

[![Code DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23426053.svg)](https://doi.org/10.5281/zenodo.23426053) [![Data DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23418954.svg)](https://doi.org/10.5281/zenodo.23418954) [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Code, data split and results of the article

> **MAPIMALA: a reproducible low-compute benchmark of neural classifiers for medicinal-plant identification from leaf images, with robustness and shortcut analysis.** *Machine Vision and Applications* (submitted, 2026).

The benchmark fixes the data, the split and the evaluation of the public **DIMPSAR** plant-image subset (5,945 smartphone images, 40 Indian medicinal species) and varies the representation fed to the classifier: raw pixels, PCA, a CNN trained from scratch, five frozen ImageNet backbones (VGG16, MobileNetV3-Large, EfficientNetV2-B0, DenseNet121, ResNet50) and three fine-tuned backbones (three seeds each). Every model is reported with 95% Wilson intervals, exact McNemar tests (Holm-corrected), CPU cost, accuracy under nine smartphone-acquisition corruptions (**DIMPSAR-C**) and a shortcut analysis (Grad-CAM attribution on the leaf, leaf-only / background-only accuracy, background-only classifier).

## Main results (test set, 1,190 images)

| Model | Accuracy (%) | 95% CI | CPU latency (ms/image) |
|---|---|---|---|
| BP network, pixels 64×64 | 39.1 | 36.3–41.9 | — |
| CNN from scratch | 65.4 | 62.6–68.0 | 123 |
| VGG16 frozen + head | 92.0 | 90.3–93.4 | 685 |
| MobileNetV3-Large frozen + head | 95.8 | 94.5–96.8 | 121 |
| EfficientNetV2-B0 frozen + head | 95.9 | 94.6–96.9 | 155 |
| DenseNet121 frozen + head | 93.9 | 92.4–95.2 | 363 |
| ResNet50 frozen + head | 94.2 | 92.7–95.4 | 362 |
| MobileNetV3-Large fine-tuned (3 seeds) | 97.3 ± 1.3 | — | 122 |
| EfficientNetV2-B0 fine-tuned (3 seeds) | 96.2 ± 0.8 | — | 160 |
| DenseNet121 fine-tuned (3 seeds) | 96.3 ± 0.8 | — | 326 |

Latency: median, batch size 1, two-core Google Colab CPU runtime, TensorFlow 2.21. A classifier trained on **background-only** images (leaf masked out) reaches 87.4% [85.4–89.2] (chance 2.5%): see Sect. 4.6 of the paper. Full tables are in `results/`.

## Data

Download the DIMPSAR plant-image subset (CC BY 4.0) from Mendeley Data, https://doi.org/10.17632/748f8jkphb.3 (also mirrored on Kaggle as *Indian Medicinal Plant Image Dataset*). The scripts expect one sub-folder per species:

```
Medicinal plant dataset/
  Aloevera/*.jpg
  Amla/*.jpg
  ...            (40 folders)
```

`results/split.json` lists the relative path of every image and the train / validation / test indices (stratified 70/10/20, seed 42: 4,161 / 594 / 1,190 images). Every script reuses it, so all models are evaluated on exactly the same test images. Do not delete it: the scripts would create a new split.

## Setup

```bash
pip install -r requirements.txt
```

Tested with Python 3.12, TensorFlow 2.21 / Keras 3 on Google Colab (CPU and T4 GPU runtimes). OpenCV is optional (GrabCut fallback of the leaf masks).

## Reproducing the paper

Replace `DIR` by the dataset folder. Times are those measured for the paper.

| Step | Command | Produces | Paper | Time |
|---|---|---|---|---|
| 1 | `python 01_extract_features.py --data DIR --backbones vgg16,mobilenetv3l,efficientnetv2b0,densenet121,resnet50` | `features/*.npz`, `results/backbone_cost.json` | Sect. 3.3.4, 4.4 | 3–61 min per backbone (CPU) |
| 2 | `python 02_probe_and_ablation.py --data DIR --backbones vgg16,mobilenetv3l,efficientnetv2b0,densenet121,resnet50` | frozen heads, CNN from scratch, representation × classifier grid (`results/ablation_grid.csv`), `models/*.keras` | Tables 3, 6 | ≈ 4 h (CPU, mostly the CNN) |
| 3 | `python 03_finetune.py --data DIR --backbones mobilenetv3l,efficientnetv2b0,densenet121 --seeds 42,43,44` | fine-tuned models | Tables 3, 4, 7 | 3–14 min per run (T4 GPU) |
| 3b | `python 03_finetune.py --data DIR --backbones mobilenetv3l,efficientnetv2b0 --seeds 43 --no-augment` | `*_ft_noaug_seed43` | Sect. 4.5 | 3–5 min per run (T4) |
| 4 | `python 04_robustness.py --data DIR` | `cache/dimpsar_c/*.npy`, `results/robustness*.csv` | Table 8, Fig. 6 | ≈ 25 min (T4) |
| 5 | `python 05_shortcut.py --data DIR` | `results/shortcut.csv`, `results/shortcut_background_classifier.json`, `cache/leaf_masks_*.npy`, `figures/gradcam_panel.pdf` | Table 9, Fig. 7 | ≈ 35 min (CPU) |
| 6 | `python 06_make_tables.py --data DIR` | `summary_main.csv`, `mcnemar.csv`, `per_class.csv`, `confused_pairs.csv`, `cost.csv`, `summary.md`, `predictions_test.csv` | Tables 3, 4, 5, 7 | seconds |
| 7 | `python 07_latency_cpu.py --data DIR` | `results/latency_cpu.csv` | Table 7, Fig. 5 | ≈ 20 min (CPU) |
| 8 | `python 08_bp_pixels.py --data DIR` | `eval_bp_pixels.json` (BP network on [0, 1] pixels) | Table 3 | ≈ 3 min (CPU) |

`run_all.sh` / `run_all.bat` chain the steps. `--limit N` (steps 1–5) runs on N images per subset for a quick dry run.

To evaluate the published models without retraining, download the Zenodo record (https://doi.org/10.5281/zenodo.23418954) and place its files as follows: `*.keras` → `models/`, `features_<backbone>.npz` → `features/<backbone>.npz`, `split.json` → `results/split.json`, unzip `leaf_masks.zip` and `predictions.zip` at the root. Steps 4–7 then run directly on these models; step 4 rebuilds DIMPSAR-C in `cache/dimpsar_c/` (≈ 10 min on a CPU) and the arrays can be compared with the record's `dimpsar_c_sha256.txt`:

```bash
sha256sum -c dimpsar_c_sha256.txt      # from the repository root, after step 4
```

Figures 1, 5 and 6 of the paper are regenerated from `results/` by `python paper/make_fig1.py` and `python paper/make_figs.py`.

## Repository layout

```
common.py                 split, image loading/caching, backbones, metrics (Wilson, bootstrap, McNemar, Holm)
01_ … 08_*.py             the eight steps above
results/                  every number of the paper (JSON per model + aggregated CSV)
figures/                  figures of the paper
paper/                    scripts of Figs 1, 5, 6
```

`results/shortcut_from_log.csv` gathers the per-model shortcut measurements of step 5 (CAM-in-leaf ratio, leaf-only and background-only accuracies) as used in Table 9.

## Notes

* Saved models take raw RGB 224 × 224 input in [0, 255]; ImageNet preprocessing is a layer of the model, so every model is evaluated identically.
* The three pixel-based rows of the original application (DNN, GA-BP) were trained before this pipeline; the BP row is re-run by step 8.
* Leaf masks are automatic (HSV threshold, morphology, GrabCut fallback) and adequate for aggregate ratios only (paper, Sect. 5).
* ConvNeXt-Tiny is supported by the code but was excluded from the paper on CPU-cost grounds (2.6 s per image).
